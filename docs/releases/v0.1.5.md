A measurement release: pool now measures each device, recommends how much of it to lend, adjusts that live, predicts runs before they start, and assesses how past runs went.

## What's new

- **`pool setup` measures this device and recommends agent settings.** It times 1, 2, 4… jobs at once (about 15 seconds), saves the result, and recommends max jobs (the fewest that reach 90% of top speed, leaving a quarter of the threads for you and fitting in memory), lending on battery, the busy threshold and the allowed devices, each with a reason. It installs only after you confirm (or with `--yes`); on Linux and macOS it prints the `pool agent` command to run instead.
- **`pool advise` compares every device in the pool:** its capacity, its share, how much faster the pool runs than this device alone, and what to change.
- **`pool map --dry-run` predicts a run without starting it:** each device's slots, time per task and share of the tasks, and with `--task-time` the run time against this device alone. In a live check it predicted 1.35× and a 112/48 split; the run measured 1.31× and 112/48.
- **`pool report` assesses past use from every device's agent log:** speed by number of jobs at once (next to what `pool setup` predicted), how much runs at the same load vary, how fully job slots were used, and how jobs ended, with requests refused because the caller couldn't be identified counted apart from devices that aren't allowed. Use `--log FILE` for a copied log.
- **Each agent lowers its job limit live** while other programs use the CPU or free memory runs short, keeping a reserve for you (the larger of 1 GB and a tenth of RAM). `--max-jobs` is now a ceiling. Jobs beyond the limit are refused with the reason; running jobs are never stopped.

## What's fixed

- **The busy threshold no longer counts the agent's own jobs** (Windows and Linux). A desktop lending 15 of 20 threads used to pause itself on its own jobs; 160 benchmark tasks now take 25.2s instead of 33.7s.
- **An agent that hadn't measured a job yet could get stuck taking none** when free memory was above your reserve but below its 512 MB guess. It now runs one job at a time until it has measured one.
- **Allowed devices were refused when Tailscale was slow to identify them.** On a busy device `tailscale whois` can outlast a status check, which canceled it, so the lookup never reached the agent's cache and the same device was refused again and again (88 times in one evening on a saturated desktop). The lookup now finishes even when the caller gives up, successful lookups are cached for a minute and refreshed before they expire, and a caller that still can't be identified gets 503 ("busy, try again") instead of 403. `pool run` and `pool map` move on as with any busy agent, and `pool nodes`, `advise`, `report` and the dashboard say the agent is busy instead of telling you to add the device to `--allow`. Devices that are identified and not allowed still get 403, and a removed device loses access within a minute.
- **On Windows, reading the agent's log while it rotated could empty the log.** Rotation now waits until the log isn't open elsewhere.
- **A refused request can no longer add fake lines to the agent's log** through its URL.

## Agents and logs

Agents now serve their log to allowed devices at `/v1/log` (which `pool report` uses) and log times to the microsecond. `pool install` already logs to a file; on Linux and macOS, keep the `--log-file` in the command `pool setup` prints, or the agent has no log to share.

Upgrade every agent to get the live job limit and to let `pool report` read its log. An older agent's log can still be assessed: copy its `agent.log` and use `pool report --log`.

## Install

1. Download the binary for your platform below, and `SHA256SUMS`.
2. Verify it:
   - Linux/macOS: `sha256sum -c SHA256SUMS --ignore-missing`
   - Windows: `Get-FileHash pool-0.1.5-windows-amd64.exe` and compare.
   - Build provenance: `gh attestation verify pool-0.1.5-windows-amd64.exe --repo montjeffrey/compute-pool`
3. Rename it to `pool` (or `pool.exe`) and put it on your `PATH`.

To upgrade a Windows agent, run `pool install` with the same flags as before from an elevated shell, so the agent keeps starting at boot. Or run `pool setup` to measure the device and get recommended flags.

See the [v0.1.0 notes](https://github.com/montjeffrey/compute-pool/releases/tag/v0.1.0) for what pool does, and [SECURITY.md](https://github.com/montjeffrey/compute-pool/blob/v0.1.5/SECURITY.md) before you run an agent.

## Known limits

- **Binaries are not code-signed yet.** Windows may show "Unknown publisher" or a SmartScreen warning, and on a PC with Smart App Control turned on it may refuse to run them at all ("An Application Control policy has blocked this file"). Smart App Control judges each file separately, so one release can run while the next is blocked. On macOS, clear the quarantine flag with `xattr -d com.apple.quarantine pool`.
- **macOS can't measure CPU load yet**, so there the busy threshold never pauses the agent and the live job limit follows free memory only.
- **`pool report` reads log times in the reporting device's time zone.** Logs from a device in another zone show shifted times.
- **From a non-elevated shell, `pool install` can't read the running agent's flags**, so it says so instead of confirming them.
