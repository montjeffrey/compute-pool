A fix release: `pool install` now applies new flags straight away.

## What's fixed

- **Re-running `pool install` restarts the agent with its new flags.** Before, the task was updated but an agent that was already running kept its old flags until it next restarted: the watchdog trigger could relaunch the old agent mid-install, and Task Scheduler then ignored the new start. Install now stops the agent again after registering the task, starts it, and checks that the running agent has the new flags. It reports an error if the old flags are still in use or no agent started.
- **Running `pool install` or `pool uninstall` from the installed copy works.** Agents are now found by their command line instead of their path, and the process running the command is never stopped.

This removes the v0.1.2 known limit about restarting the agent by hand.

## Install

1. Download the binary for your platform below, and `SHA256SUMS`.
2. Verify it:
   - Linux/macOS: `sha256sum -c SHA256SUMS --ignore-missing`
   - Windows: `Get-FileHash pool-0.1.3-windows-amd64.exe` and compare.
   - Build provenance: `gh attestation verify pool-0.1.3-windows-amd64.exe --repo montjeffrey/compute-pool`
3. Rename it to `pool` (or `pool.exe`) and put it on your `PATH`.

To upgrade a Windows agent, run `pool install` with the same flags as before from an elevated shell, so the agent keeps starting at boot.

See the [v0.1.0 notes](https://github.com/montjeffrey/compute-pool/releases/tag/v0.1.0) for what pool does, and [SECURITY.md](https://github.com/montjeffrey/compute-pool/blob/v0.1.3/SECURITY.md) before you run an agent.

## Known limits

- **Binaries are not code-signed yet**, so Windows may show "Unknown publisher" or a SmartScreen warning. On macOS, clear the quarantine flag with `xattr -d com.apple.quarantine pool`.
- **From a non-elevated shell, `pool install` can't read the running agent's flags**, so it says so instead of confirming them.
